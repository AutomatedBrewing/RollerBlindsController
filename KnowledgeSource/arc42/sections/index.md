# arc42 Section

* [Architecture Constraints](architecture-constraints.md) - Documents all constraints — organizational, technical, or regulatory — that restrict design and architecture decisions.
* [Architecture Decisions](architecture-decisions.md) - Records important, hard-to-reverse architecture decisions along with their context, alternatives considered, and rationale.
* [Building Block View](building-block-view.md) - Describes the static decomposition of the system into building blocks arranged in hierarchical whitebox and blackbox levels.
* [Context and Scope](context-and-scope.md) - Defines the system boundary and describes all external interfaces in both business and technical terms.
* [Cross-cutting Concepts](cross-cutting-concepts.md) - Documents overarching, recurring solution patterns, principles, and concepts that span multiple building blocks or subsystems.
* [Deployment View](deployment-view.md) - Describes the technical infrastructure and how software building blocks are mapped onto hardware and infrastructure elements across deployment levels.
* [Glossary](glossary.md) - Defines important domain-specific and technical terms used throughout the architecture documentation to ensure shared understanding.
* [Introduction and Goals](introduction-and-goals.md) - Defines the essential requirements, top quality goals, and key stakeholder expectations that drive the architecture of the system.
* [Quality Requirements](quality-requirements.md) - Specifies quality goals with concrete quality scenarios that define measurable acceptance criteria for the architecture.
* [Risks and Technical Debts](risks-and-technical-debts.md) - Identifies known technical risks and accumulated technical debt that may affect the system's quality or evolvability.
* [Runtime View](runtime-view.md) - Illustrates the dynamic behavior of the system through runtime scenarios showing how building block instances interact.
* [Solution Strategy](solution-strategy.md) - Summarizes the fundamental decisions and solution approaches that shape the architecture in response to quality goals and constraints.
