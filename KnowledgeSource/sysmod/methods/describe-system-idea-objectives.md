# Purpose

The System Idea and System Objectives need to be known to all participating parties so they can make the right decisions on the way to the final system. They must be actively communicated.

# Description

The System Idea is the elevator pitch of your system—short, precise, concise, and unique—telling every project member the basic notion of the system that can be communicated during an elevator ride.

The System Idea and System Objectives are part of the system model to communicate them and to link them with system artifacts like Requirements. Various sources can feed them: a genius idea, a given contract, an output of product management work, or a Design Thinking process.

Often, this method only works up a somewhere-given notion and objectives of the system into model artifacts for communication inside the development project team. The outcome is stored or referenced in the system model.

Practical workshop tools to elaborate the idea and objectives include the Product Box, the Product Vision Board by Roman Pichler, and the SAMS method with storyboards.

The Requirements for the system should support the objectives. The relationship in the model is a trace from the Requirements to the System Objectives.
