# SYSMOD Method

* [Analyze the Problem](analyze-problem.md) - Find out the real problem that should be resolved by the system by performing a profound analysis beyond the initial problem statement.
* [Define System States](define-system-states.md) - Define the states, state transitions, and state-controlled functions of the system and parts of the system that constrain the execution of functions.
* [Deploy the MBSE Methodology](deploy-mbse-methodology.md) - Deploy the customized MBSE Methodology in the organization to enable its active adoption and successful application.
* [Describe the Base Architecture](describe-base-architecture.md) - Define the given physical architecture at the project start that constrains the solution space and sets the abstraction level for system requirements.
* [Describe the System Idea and System Objectives](describe-system-idea-objectives.md) - Describe the core idea and main objectives of the system so they are known to all project members and can drive the right decisions throughout the development.
* [Identify Stakeholders](identify-stakeholders.md) - Identify all individuals and organizations that may have requirements or an interest in the system, including their concerns and contact information.
* [Identify System Processes](identify-system-processes.md) - Describe the logical order of execution of the System Use Cases to make dependencies and valid execution sequences explicit.
* [Identify System Use Cases](identify-system-use-cases.md) - Identify all services of the system provided for the actors and stakeholders, providing an outside-in view of system functions from the perspective of system actors.
* [Identify the System Context](identify-system-context.md) - Identify all users and other external entities that interact with the system, defining the system boundary, interfaces, and relevant item flows.
* [Model Risks](model-risks.md) - Specify the business, organizational, and technical risks in the system model and link them to other model elements for traceability.
* [Model Requirements](model-requirements.md) - Specify the requirements in the system model, representing the contract between the stakeholders and the systems engineers who build the system.
* [Model the Domain Knowledge](model-domain-knowledge.md) - Define the terms of the domain from the perspective of the system, specifying the semantic and structure of domain objects used by the system.
* [Model the Functional Architecture](model-functional-architecture.md) - Model an architecture that is based only on functions, independent of the technical implementation, providing a bridge between functional requirements and physical architectures.
* [Model the Logical Architecture](model-logical-architecture.md) - Model a physical architecture on a high abstraction level that satisfies the given requirements, describing the technical concepts and principles of the system.
* [Model the Product Architecture](model-product-architecture.md) - Model a concrete specification of the physical architecture as the most detailed system architecture specification in the system model.
* [Model the Test Architecture](model-test-architecture.md) - Model the setup of the test system and the system under test, specifying the configurations needed to perform the test cases.
* [Model Use Case Activities](model-use-case-activities.md) - Model the behavior of the System Use Cases by specifying their functional decomposition, sequence of execution, and object flow between system functions.
* [Provide MBSE Training and Coaching](provide-mbse-training-coaching.md) - Train the MBSE Methodology and related modeling languages and tools, and provide coaching to assist in applying the MBSE Methodology.
* [Revise an Architecture with Scenarios](revise-architecture-scenarios.md) - Revise a system architecture with usage scenarios that map paths through use case activities to architecture elements, verifying all necessary parts and interfaces are correctly defined.
* [Set up and Maintain the SME](set-up-maintain-sme.md) - Configure the modeling tools and create a System Modeling Environment (SME) for the project or organization.
* [Specify Test Cases](specify-test-cases.md) - Model the test cases that verify and validate the requirements, closing the loop from system requirements through the architecture and back to the requirements.
* [Tailor the MBSE Methodology](tailor-mbse-methodology.md) - Tailor a given MBSE Methodology to the specific needs of an organization or project by adapting its processes, methods, products, roles, and tools.
