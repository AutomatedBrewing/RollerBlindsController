# SYSMOD Tool

* [Coupling of System Architectures](coupling-system-architectures.md) - A pattern describing loose coupling (allocate relationship) and strong coupling (generalization relationship) between different SYSMOD architecture kinds, with trade-offs between both approaches.
* [Functional Architectures for Systems (FAS)](functional-architectures-for-systems.md) - The FAS method derives a technology-independent Functional Architecture from Use Case Activities by grouping system functions based on functional cohesion, providing a bridge between functional requirements and physical architectures.
* [Model Purpose Model](model-purpose-model.md) - The SYSMOD Model Purpose Model describes three levels of modeling objectives (Communication, Traceability, Specification) that represent increasing capabilities of modeling, guiding MBSE adoption.
* [Proxy versus Full Port](proxy-versus-full-port.md) - A SysML modeling pattern recommending the exclusive use of proxy ports over full ports for specifying block interfaces, simplifying models and ensuring consistent part property representation.
* [The Death of the Actor](death-of-actor.md) - An MBSE pattern recommending the use of SysML Block instead of the SysML Actor model element to represent system actors, enabling internal structure modeling, port specification, and flexible viewpoint changes.
* [Variant Modeling](variant-modeling.md) - An approach to model system variants using SYSMOD and the VAMOS (Variant Modeling with SysML) method, enabling specification of product families and variant configurations in the system model.
* [Workshop Tool: 6M Method](6m-method.md) - The 6M method is a cause and effect analysis tool using six categories (manpower, machinery, materials, methods, measurement, mother-nature) to explore potential causes leading to a problem statement.
* [Workshop Tool: Five Whys Method](five-whys-method.md) - The Five Whys method systematically identifies the root cause of a problem by asking the question "Why?" five times, following the cause-effect chain to its origin.
* [Workshop Tool: Product Box](product-box.md) - The Product Box is a workshop tool using a physical cardboard box to develop the System Idea and System Objectives by labeling it with a product name, customer objectives, and main features.
* [Workshop Tool: Product Vision Board](product-vision-board.md) - The Product Vision Board is a canvas proposed by Roman Pichler providing an overview of the main pillars of a product vision, covering System Idea, System Objectives, and stakeholder aspects.
* [Workshop Tool: SAMS Method](sams-method.md) - The Storyboard Activity Modeling for Systems (SAMS) method supports the elaboration of system use cases based on storyboards, establishing traceability between storyboard snippets and the resulting system models.
* [Zigzag Pattern](zigzag-pattern.md) - The Zigzag Pattern describes the iterative what/how relationship between requirements and architectures across multiple abstraction levels, showing that requirements always contain implicit solution aspects.
