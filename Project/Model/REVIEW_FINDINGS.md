standard library element. Logged as **MR-027**. MR-004 is kept in the table
below marked `Invalid` for audit trail; it does not count toward the open
Critical total (replaced by MR-027).

## Fixes applied beyond the original 26 findings

While executing the fix plan, direct file inspection surfaced a few additional
stale/inconsistent references that were tightly coupled to the findings above
and were corrected in the same pass (not logged as separate MR-IDs, since they
are direct consequences of the MR-011/MR-016/MR-017/MR-026 fixes, not new
independent defects):
- `Requirements.sysml`, `SystemObjectives.sysml`, `Risks.sysml`, `Scenarios.sysml`:
  ~17 prose `verificationMethod`/`mitigation`/`rationale` strings referencing the
  deleted `Verification::Functional/Quality/Constraints/Safety::VerifyX` defs
  (including one, `Verification::Safety::VerifyCommandArbitration`, that was
  already a broken reference to a non-existent package *before* this pass) were
  updated to reference the real `SystemTestCases::<Package>::TC_*` test cases.

  updated to remove the dangling forward-reference.
- `BaseArchitecture.sysml`, `ProductArchitecture.sysml`, `LogicalArchitecture.sysml`:
  header comments explaining the "avoid name collision" import pattern were
  updated to reflect that `SystemArchitecture_Taxonomy` no longer has any
  per-layer headers to collide with (per the MR-016 fix).
- `ProblemStatement.sysml`/`SystemIdea.sysml`/`Requirements.sysml`/`SystemObjectives.sysml`:
  all `frame`/`source` references to the old bare `NeedForConvenientShutterOperation`
  usage were updated to the new typed usage name `needForConvenientShutterOperation`.
